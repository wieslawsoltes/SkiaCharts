## Technical Specifications

### Performance Characteristics
- **Legend Layout**: O(n) for n items - single pass
- **Legend Hit Test**: O(n) for n items - linear search
- **Label Layout**: O(n*m) for n labels, m placements - worst case
- **Collision Detection**: O(n²) for n labels - checks against all prior labels
- **Title Layout**: O(1) - fixed calculation
- **Rendering**: O(n) for n items/labels - single pass

### Memory Footprint
- LegendManager: ~300 bytes + O(n) for n items
- LegendItem: ~100 bytes per item
- DataLabelManager: ~400 bytes + O(n) for n labels + O(n) for occupied regions
- DataLabel: ~120 bytes per label
- TitleManager: ~200 bytes
- Total per chart (legend + labels + title): ~900 bytes + items/labels

### Thread Safety
- Not thread-safe by design (UI thread only)
- Event handlers execute synchronously
- No internal locking required

## Collision Detection Algorithm Details

The label collision detection uses a sophisticated algorithm:

1. **Sequential Processing**: Labels processed in order added
2. **Preferred Placement First**: Each label tries its preferred position
3. **Bounds Checking**: Verify position is within chart bounds
4. **Collision Testing**: Check against all previously placed labels
5. **Alternative Placements**: If collision, try alternatives in order
6. **Fallback**: If no valid position, label marked as not visible
7. **Occupied Region Tracking**: Successfully placed labels tracked

**Example**:
```
Label 1: Position (100, 100), Placement: Top
  → Try Top: Valid, no collisions
  → Placed at Top position
  → Add to occupied regions

Label 2: Position (100, 100), Placement: Top
  → Try Top: Collision with Label 1
  → Try Bottom: Valid, no collision
  → Placed at Bottom position
  → Add to occupied regions

Label 3: Position (100, 100), Placement: Top
  → Try Top: Collision
  → Try Bottom: Collision
  → Try Right: Valid, no collision
  → Placed at Right position
```
