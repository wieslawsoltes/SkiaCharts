## Technical Highlights

### 1. Unified Bar/Column Implementation

**Design Decision**: Single `BarChart` class handles both orientations
```csharp
if (config.Orientation == BarOrientation.Vertical)
{
    // Vertical bars (column chart)
    p1 = viewport.DataToScreen(x, y1);
    p2 = viewport.DataToScreen(x + width, y2);
}
else
{
    // Horizontal bars (bar chart)
    p1 = viewport.DataToScreen(y1, x);
    p2 = viewport.DataToScreen(y2, x + width);
}
```

**Benefits**:
- Single codebase to maintain
- Configuration-based orientation switching
- Shared rendering logic

### 2. Percentage Stacking Algorithm

**Challenge**: Calculate percentages while handling zero totals
**Solution** (lines 160-178 in BarChart.cs):
```csharp
// Calculate totals for each category
var totals = new Dictionary<double, double>();
foreach (var x in sortedX)
{
    double total = 0;
    foreach (var series in _allSeries)
    {
        total += Math.Abs(point.Y);
    }
    totals[x] = total > 0 ? total : 1; // Avoid division by zero
}

// Convert to percentages
if (percentage && totals[x] > 0)
{
    value = (value / totals[x]) * 100;
}
```

**Key Features**:
- Uses absolute values for totals
- Prevents division by zero
- Per-category calculation

### 3. Gradient Rendering

**Algorithm** (lines 288-305 in BarChart.cs):
```csharp
var angle = style.GradientAngle * (float)Math.PI / 180f;
var dx = (float)Math.Cos(angle);
var dy = (float)Math.Sin(angle);

var startPoint = new SKPoint(
    rect.MidX - dx * rect.Width / 2,
    rect.MidY - dy * rect.Height / 2
);
var endPoint = new SKPoint(
    rect.MidX + dx * rect.Width / 2,
    rect.MidY + dy * rect.Height / 2
);

fillPaint.Shader = SKShader.CreateLinearGradient(
    startPoint, endPoint,
    style.GradientColors,
    null,
    SKShaderTileMode.Clamp
);
```

**Features**:
- Angle-based gradient direction
- Centered on bar rectangle
- Works with any bar size

### 4. Minimum Bar Size Logic

**Purpose**: Ensure small values are still visible
**Implementation** (lines 240-253 in BarChart.cs):
```csharp
var height = Math.Abs(p2.Y - p1.Y);
if (height < style.MinimumBarSize && y2 != y1)
{
    if (y2 > y1)
    {
        p2.Y = p1.Y + style.MinimumBarSize;
    }
    else
    {
        p2.Y = p1.Y - style.MinimumBarSize;
    }
}
```

**Benefits**:
- Handles positive and negative values
- Applied in screen space (pixels)
- Preserves visual feedback for tiny values

## Architecture Decisions

### 1. Enum-Based Configuration

**Rationale**: Type-safe, discoverable API
```csharp
public enum BarStackMode { None, Absolute, Percentage }
public enum BarOrientation { Vertical, Horizontal }
```

**Benefits**:
- IntelliSense support
- Compile-time validation
- Clear documentation

### 2. Separate Style and Configuration

**BarSeriesStyle**: Per-series visual properties
- Fill color
- Border color/width
- Corner radius
- Gradient settings
- Bar width ratio

**BarChartConfiguration**: Chart-level behavior
- Stack mode
- Orientation
- Group spacing
- Value labels

**Rationale**: Clear separation of concerns
- Style = how bars look
- Configuration = how bars behave

### 3. Dictionary-Based Style Management

**Same pattern as LineChartEnhanced**:
```csharp
private readonly Dictionary<IDataSeries<IDataPoint>, BarSeriesStyle> _seriesStyles = new();
```

**Benefits**:
- Flexible per-series styling
- Data remains immutable
- Easy to change styles
